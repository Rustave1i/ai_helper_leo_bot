# PRINCIPLES

Статус: Active
Версия: 1.0

---

# Назначение

Этот документ определяет инженерные принципы разработки Leo.
Любое архитектурное решение должно соответствовать данным принципам.
Если новый компонент нарушает один или несколько принципов, решение должно быть пересмотрено или оформлено отдельным ADR.

---

# 1. Один интеллект

В системе существует только один компонент, принимающий интеллектуальные решения — AI.
Все остальные компоненты являются инфраструктурой.
Они не анализируют данные и не принимают решений.

---

# 2. AI принимает решения

AI самостоятельно определяет:

- достаточно ли информации;
- каких данных не хватает;
- какие источники необходимо использовать;
- когда нужно задать уточняющий вопрос;
- когда можно сформировать окончательный ответ.

---

# 3. Platform API выполняет

Platform API не принимает решений.
Он только предоставляет AI доступ к возможностям платформы.
Platform API никогда не делает выводов и не изменяет смысл полученных данных.

---

# 4. Все начинается с разговора

Каждое сообщение сначала сохраняется в Conversation Store.
Только после сохранения начинается его обработка.
История разговора является главным источником контекста.

---

# 5. Conversation важнее отдельных сообщений

Leo анализирует разговор целиком.
Ответ никогда не должен строиться только на одном сообщении, если существует необходимый контекст.

---

# 6. Получить информацию лучше, чем предположить

Если AI считает, что информации недостаточно, он должен:

1. запросить необходимые данные у Platform API;
2. при необходимости задать уточняющий вопрос пользователю;
3. только после этого формировать окончательный ответ.

---

# 7. Platform API ничего не придумывает

Platform API возвращает только фактические данные.
Он не анализирует их, не ранжирует и не делает выводов.
Все выводы делает AI.

---

# 8. Каждый компонент имеет одну ответственность

Каждый компонент платформы отвечает только за одну задачу.

Например:

- Telegram Adapter получает события Telegram;
- Conversation Store хранит данные;
- Platform API предоставляет доступ к данным;
- Leo AI принимает решения.

---

# 9. Документация первична

Новый компонент сначала проектируется.
После согласования архитектуры создается документация.
Только затем начинается разработка.

---

# 10. Никакого кода "на будущее"

Компоненты появляются только тогда, когда становятся необходимыми для реализации реального сценария.
Платформа развивается постепенно.

---

# 11. Простота важнее сложности

Если задачу можно решить несколькими способами, предпочтение всегда отдается наиболее простому решению.
Сложность должна иметь объективное обоснование.

---

# 12. Leo помогает человеку думать

Leo не принимает решения вместо пользователя.
Leo предоставляет информацию, объясняет различные точки зрения и помогает человеку принять собственное решение.

---

# 13. Архитектура не зависит от AI-провайдера

Платформа должна одинаково работать независимо от используемой языковой модели.
Замена AI-провайдера не должна требовать изменения архитектуры приложения.

---

# 14. Источники информации взаимозаменяемы

Conversation Store, Internet, документы и другие источники являются равноправными источниками информации.
AI самостоятельно определяет, какой источник необходимо использовать.

---

# 15. Любое изменение архитектуры фиксируется

Любое значимое архитектурное решение оформляется отдельным ADR.
История принятых решений сохраняется.
